## Branch コンベンション 

```
main: 最終デプロイ (ver 1.0)
dev: 次のバージョンの準備 (ver 2.0)
feature/関連項目: 関連項目に対する機能実装

```

1. 複数の feature ブランチが作成され、完了した場合、dev ブランチに PR を作成する。
2. PR に対するコードレビューの進行 (規約の遵守、効率性、改善点など)
3. レビュー通過時に Merge

## Commit コンベンション

### Format

```
type: subject

body

```

<br>

## コンベンションガイド 

### type

* 1つのコミットに複数のタイプが存在する場合、優先順位が高いタイプを使用する。
* fix: バグ修正
* feat: 新機能の追加
* refactor: リファクタリング (バグ修正や機能追加を伴わないコードの変更)
* docs: ドキュメントのみの変更
* style: コードの意味が変更されない場合 (スペース、フォーマット、改行など)
* test: テストコードの追加/修正
* chore: ビルド、テストのアップデート、パッケージマネージャーを設定する場合 (プロダクションコードの変更なし)

### subject

* タイトルは50文字を超えないようにする。
* 簡潔な表現 (体言止めなど) を使用する。
* 重要かつ核心的な要素だけを抜粋して (項目別に列挙するように) 表現する。
* 最後に特殊文字を入れない。(ピリオド、感嘆符、疑問符など)

### body (optional)

* 各行は箇条書き (Bullet list) で表示する。
   * 例) - AA
* なるべく1行あたり72文字を超えないようにする。
* 本文の量にとらわれず、できるだけ詳細に記述する。
* 「どのように」よりも「何を」「なぜ」変更したのかを説明する。
